# Pixel construction for application icons

Read when designed pixel clusters and stepped contours define the icon. Pixel art is a construction method; retro, playful, or restrained are optional directions. Add [character construction](characters.md) for creatures or mascots, and follow the [workflow](workflow.md) for selection and delivery.

## Establish the grid

Choose a logical working grid appropriate to the subject, requested appearance, and intended display sizes. Record it separately from the export dimensions. Design the silhouette and main color clusters on that grid; enlarging a bitmap or applying a pixelation filter does not by itself establish intentional pixel construction.

Use a consistent vocabulary for stair steps, corners, curves, and line thickness. A deliberately mixed grid needs a visible organizing rule. Choose the palette for distinguishable roles and expression; do not force a nostalgic game palette when the brief does not call for one.

## Clusters, expression, and shading

Make the identifying feature readable through connected color clusters and important gaps. Avoid isolated pixels that create unintended facial details, debris, or false highlights. Shape and cluster placement determine expression when there is little room for features.

Use discrete value groups to explain volume when needed. Dithering is optional and must be inspected at actual size; dense patterns can become noise. For dimensional influence, express the light and volume within the selected grid rather than adding smooth reflections that contradict it. The grid takes precedence when native pixel construction is promised.

## Scaling and platform adaptation

Preserve the logical grid in the source. Use integer nearest-neighbor enlargement for crisp study views when appropriate, and inspect actual platform resampling separately. A target display size may not map to an integer scale; derive an optical variant or disclose the softened result instead of claiming every size is pixel-perfect.

Keep display masks and platform layers distinct from the pixel construction. Respect [platform execution](platforms.md) while preserving the motif, palette relationships, and cluster rhythm; fixed grid choices do not override target delivery requirements.

## Production and inspection

Add the intended grid, palette roles, cluster language, shading, and scaling expectations to the render brief. Image generation may help explore pixel-looking concepts. When native pixel art is requested, verify the grid and correct clusters with controlled pixel editing before claiming that deliverable. Otherwise label the result as a pixel-style raster.

Inspect uneven edge steps, unintended isolated pixels, merged gaps, expression drift, palette noise, and nonuniform scaling. Check the logical source, enlarged study, and intended display versions separately. Reduce detail or redesign clusters when the identifying feature fails; a retro frame cannot repair it.
